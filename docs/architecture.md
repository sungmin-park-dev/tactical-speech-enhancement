# 처리 구조와 시간 계약

## 책임 분리

캡처 제어부는 매 프레임마다 **입력 검사 → 송신할 원본 구간 선택 → 유효
입력의 추론 제출** 순서로 실행한다. 입력 검사는 모델 대기열에 넣기 전에
수행한다. 유지·정상 확인·복귀 상태와 이득은 캡처 제어부만 변경한다.

모델 작업자는 순번과 보호 세대를 가진 작업을 받아 추론한다. 모델 상태
초기화도 이 작업자 안에서 처리하며 보호 상태를 변경하지 않는다. 새 입력
이상이 발생하면 보호 세대가 바뀐다. 과거 세대·마감 이후·이미 송신한 순번의
결과는 선택되지 않는다. 원본 구간에 붙은 음소거 판정도 결과 도착으로
덮어쓸 수 없다.

GTCRN은 스펙트럼과 재귀 캐시를 처리하는 스트리밍 모델이다. 입력 작업
`n`의 합성 결과는 원본 구간 `n−1`에 대응한다. 캡처 틱 `n`에서는 원본
`n−2`를 송신하며 원음도 같은 구간으로 정렬한다. 입력 프레임 수집 완료부터
선택까지의 일정은 **32ms**다. 이것을 기기 종단 지연으로 해석하지 않는다.
원본 구간을 보존하는 가짜 모델과 실제 ONNX 모델을 구분하여 시험한다.

[GTCRN 공식 구현](https://github.com/Xiaobin-Rong/gtcrn)을 모델 출처로 삼고,
배포 ONNX의 해시와 입출력 모양을 고정한다. 이번 공개본에서는 기존
스트리밍 모델을 유지하여 모델 변경과 실행 구조 변경의 영향을 섞지 않는다.

## 버퍼별 한도

| 버퍼 | 한도 | 지연과 폐기 규칙 |
|---|---|---|
| 입력 검사 | 별도 대기열 없음 | 캡처 직후 검사 |
| 추론 작업 | 실행 중 1 + 최신 대기 1 | 대기 교체로 생긴 순번 공백 뒤 모델 초기화 |
| 추론 결과 | 원본 순번별 최대 2 | 슬롯을 채우려고 기다리지 않음, 늦은 결과 폐기 |
| 원음 정렬 | 고정 2프레임 | 추론 장애에도 늘리지 않음 |
| 송신 준비 | 최신 패킷 1 | 오래된 패킷 폐기, 순번 유지 |
| 수신 지터 | 목표 4·최대 8프레임 | 최초 유효 패킷 도착 후 64ms에 재생 시작 |
| 재생 대기 | 별도 없음 | 지터 버퍼에서 직접 소비 |
| 지연 표본 | 최대 4,096개 | 누계와 최댓값은 표본 폐기와 무관하게 유지 |

추론 작업과 결과 저장소는 고정 원음 정렬 시간을 공유한다. 각 저장소의
최대 용량을 모두 채워서 직렬 지연을 만드는 방식이 아니다. 입력·출력 장치,
드라이버, 운영체제 네트워크 버퍼의 지연은 이 표와 별도로 측정한다.

UDP 패킷의 실행 식별자와 순번으로 손실·중복·순서 변경·상대 재시작을
처리한다. 누락 기한에는 무음을 사용하고 과도한 적체는 오래된 구간을
폐기한다. 수신 표본을 임의의 크기로 무한 적재하지 않는다.

## 보호 상태

| 입력과 상태 | 출력 선택 |
|---|---|
| 정상 입력·기한 내 모델 결과 | 향상 음성 |
| 정상 입력·모델 실패 또는 기한 초과 | 고정 지연으로 정렬한 원음 |
| 큰 피크·포화·잘못된 입력 | 해당 원본 구간 음소거, 모델에 제출하지 않음 |
| 유지 또는 정상 확인 | 음소거 |
| 복귀 | 원본 구간의 보호 이득으로 점진 복귀 |

새 이상은 송신 선택보다 먼저 반영되며 이미 버퍼에 있던 과거 세대도
차단한다. 모델만 실패한 경우는 입력 이상으로 분류하지 않는다. 모델 경로
복귀는 기한 내 결과 두 프레임을 확인한 다음 64ms 크로스페이드한다.
모든 분기·혼합·이득 처리 뒤 송신과 수신 재생에 각각 최종 리미터를 둔다.
최종 결과가 비정상 수치이면 프레임 전체를 음소거한다.

## 소프트웨어 검증용 초기값

입력은 정규화된 실수 PCM이다. 아래 값은 마이크나 음압을 교정한 결과가
아니며 실제 Pi 측정을 통해 조정할 초기 설정이다.

| 설정 | 초기값 |
|---|---|
| 큰 피크 감지 | 최대 절댓값 ≥ 0.80 |
| 포화 | 절댓값 ≥ 0.985인 샘플 2개 연속, 프레임 경계 포함 |
| 정상 확인 | 유효 입력이며 최대 절댓값 ≤ 0.60 |
| 이상 후 유지 | 64ms / 4프레임 |
| 연속 정상 확인 | 유지 종료 후 64ms / 4프레임 |
| 보호 이득 복귀 | 이후 128ms / 2,048샘플 선형 증가 |
| 시작 보호 | 정상 확인 64ms + 복귀 128ms |
| 모델 기한 | 제출 후 16ms 미만, 동일 기한 도달 시에도 폐기 |
| 모델 복귀 | 정상 결과 2프레임 + 64ms 크로스페이드 |
| 최종 출력 상한 | −6dBFS |
| 리미터 해제 | 100ms 지수형 시정수 |

유지·정상 확인·복귀 시간은 서로 겹치지 않는다. `0.60 < peak < 0.80`은
정상 상태에서 새 차단을 유발하지 않는다. 정상 확인 중에는 확인 횟수를
초기화하고, 복귀 중에는 현재 이득을 유지한다. 복귀 중 이상이 재발하면
즉시 음소거하고 유지 시간을 다시 시작한다. 정상 입력이 계속되면 복귀
이득은 단조 증가하며 시간초과만으로 보호를 강제 해제하지 않는다.

비정상 수치·잘못된 형태·PCM 범위 초과·장치 overload는 프레임 전체를
잘못된 입력으로 처리한다. 보호 이득의 복귀와 리미터의 해제는 별개다.
100ms 시정수는 정확히 그 시간이 지난 뒤 이득이 1이 된다는 뜻이 아니다.

설정 파일은 TOML이며 초기값 전체를
[software-defaults.toml](../examples/software-defaults.toml)에 제공한다.
`tse --config examples/software-defaults.toml benchmark --frames 10000`처럼
적용하며, 변경한 설정은 결과와 함께 보관한다. 모델 계약인
16 kHz·256샘플과 고정 원본 정렬은 일반적인 튜닝 항목이 아니다.
