# 설계 판단

## 문제와 설계 판단

음성 잡음 제거 모델이 좋은 출력을 만들더라도, 추론이 늦어지거나 입력이
포화되면 통신 시스템의 동작을 모델만으로 결정할 수 없다. 공개본은 입력
검사와 출력 제한을 모델 밖에 두고, 어떤 원본 구간이 어떤 결과와 연결되는지
순번과 보호 세대로 추적한다. 정상 입력의 모델 장애와 입력 자체의 이상도
서로 다른 경로로 처리한다.

GTCRN을 유지한 이유는 스트리밍 ONNX의 고정된 입출력 계약을 이용해 실행
구조를 먼저 검증하기 위해서다. 모델 비교는 실제 Pi의 처리 시간·음질을
동일 조건으로 측정할 수 있게 된 후 진행한다. 현재 선택을 모든 환경에서의
음질 우위로 해석하지 않는다.

수신 지터 버퍼에만 목표 4·최대 8프레임을 적용했다. 추론·원음·송신의
대기열에 같은 값을 반복 적용하지 않고 고정된 송신 일정 안에서 각각의
책임과 저장 한도를 정했다. 보호 상태는 추론 완료 메시지로 전환하지 않는다.
