# 개발 판단과 에이전트 협업

## 문제와 설계 판단

음성 잡음 제거 모델이 좋은 출력을 만들더라도, 추론이 늦어지거나 입력이
포화되면 통신 시스템의 동작을 모델만으로 결정할 수 없다. 공개본은 입력
검사와 출력 제한을 모델 밖에 두고, 어떤 원본 구간이 어떤 결과와 연결되는지
순번과 보호 세대로 추적한다. 정상 입력의 모델 장애와 입력 자체의 이상도
서로 다른 경로로 처리한다.

GTCRN을 유지한 이유는 스트리밍 ONNX의 고정된 입출력 계약을 이용해 실행
구조를 먼저 검증하기 위해서다. 모델 비교는 실제 Pi의 처리 시간·음질을
동일 조건으로 측정할 수 있게 된 후 진행한다. 현재 선택을 모든 환경에서의
음질 우위로 해석하지 않는다.

수신 지터 버퍼에만 목표 4·최대 8프레임을 적용했다. 추론·원음·송신의
대기열에 같은 값을 반복 적용하지 않고 고정된 송신 일정 안에서 각각의
책임과 저장 한도를 정했다. 보호 상태는 추론 완료 메시지로 전환하지 않는다.

## 두 단계의 기록

| 단계 | 역할과 근거 |
|---|---|
| 이전 장치 구현 | 프로젝트 소유자가 목표와 기술 방향을 정하고 장치 실행을 확인했다고 보고했다. Raspberry Pi 5 두 대의 모델 실행과 Wi-Fi·핫스팟 통신 달성은 소유자 보고다. 과거 상세 코드 작업·정량 수치는 이 공개본에서 복원하거나 검증하지 않았다. |
| 이번 공개본 재구성 | 사용자가 공개 범위, 원음 전환 조건, 버퍼 한도, 복귀 시간과 합격 기준을 정했다. 에이전트가 코드·문서·시험 자료를 구성하고 자동 검증을 수행했다. 현재 저장소와 검증 결과가 이 단계의 근거다. |

## 이번 작업의 분담

| 작업 | 담당 기능 | 검토 초점 |
|---|---|---|
| 통합 | 패키지, 모델 출처·무결성, 실행 명령, 장치 입출력 어댑터, 전체 검증 | 설치·실행의 일관성, 실제 모델 연결, 장치 오류와 자원 정리 |
| 보호·추론 | 입력 검사, 상태 전환, 원본 정렬, 작업·결과 대기열 | 모델 장애 중 보호 유지, 늦은 출력 차단 |
| 통신 | UDP 프로토콜, 송수신, 지터 버퍼 | 메모리 한도, 순번·재시작·시계 차이 |
| 근거·문서 | 공개 음성 자료 추출, 출처·라이선스, 정상 음성 시험, 문서 | 재현 가능한 선택, 과거 보고와 새 검증 구분 |

각 작업은 파일 소유 범위를 나누어 병렬 진행했고, 공유 인터페이스를 먼저
맞췄다. 통합 단계에서는 실제 명령·테스트 결과를 확인하여 문서의 설명과
코드 동작이 일치하는지 검토했다. 역할 분담만으로 결과의 정확성을
주장하지 않으며 합격 여부는 [검증 기준](validation.md)에 따른다.

## 검토에서 확인한 사항

- 프레임 최대값을 임계값과 비교할 때 입력 정밀도로 경계값을 표현한다.
  `float32(0.60)`의 표현 차이가 정상 확인을 불필요하게 막지 않도록 했다.
- 정상 음성 시험 앞의 무음은 정확히 1초다. 16ms 프레임과 경계가 맞지
  않으므로 음성 시작이 걸친 프레임에서도 음성 구간의 보호 이득을 검사한다.
- 음성 fixture의 파일 해시뿐 아니라 디코딩된 PCM과 원본 세그먼트의 해시도
  기록한다. 출처의 순번 정렬은 문자열 순서가 아닌 숫자 순서로 고정했다.
- 모델의 배포 저장소와 모델 원 저작자의 라이선스를 구분했다. 배포처의
  프로젝트 라이선스가 모델 라이선스를 바꾸는 것으로 표시하지 않는다.
- 장치 스트림을 여는 도중 중단하면 지연 측정값이 아직 없을 수 있다.
  이 경우를 명시적으로 표현하고, 시작이 끝나지 않아도 통신과 추론 자원을
  정리하도록 했다. 통신 종료가 실패해도 추론 정리는 실행되도록 보완했다.
- 처리 보고서에 적용 설정을 포함하고 전체 오디오 콜백 처리 시간을
  추가했다. 모델 추론 시간, 캡처 제어 시간, 전체 콜백 시간과 장치가 보고한
  지연을 구분하며 최근 표본과 전체 누계의 범위도 명시한다.
- 통신을 교차 검토하면서 재생이 멈춘 동안 수신 버퍼가 넘쳤을 때, 수신
  순번 이동과 시간 경과에 따른 순번 이동이 겹칠 수 있는 경로를 발견했다.
  수신 단계에서 이미 건너뛴 구간을 계산에 반영하여 같은 구간을 두 번
  건너뛰지 않도록 수정했다. 지속 수신 중 재생 중단과 버퍼 초과 뒤 복귀를
  확인하는 회귀 시험을 추가했다.
- 검증 설명과 실제 시험을 대조해 지속 포화, 실제 음성과 충격의 중첩,
  세 임계값의 바로 아래·동일·바로 위 조건을 보강했다. 시험 조건에 맞춰
  임계값을 바꾸지 않고 승인된 초기값의 경계 동작을 검증했다.

자동 검증 결과와 실행 환경은 검증 문서에 기록한다. 실제 Pi 측정이나 이전
작업에 대한 상세 기록을 소급하여 만들어 넣지 않는다.
