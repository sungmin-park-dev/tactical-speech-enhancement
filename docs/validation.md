# 검증 기준과 결과의 범위

## 근거의 구분

소유자는 이전 구현에서 Raspberry Pi 5 두 대의 모델 실행과 Wi-Fi·핫스팟
음성 통신 목표를 달성했다고 보고했다. 이 경험은 이번 공개본의 자동 검증과
구분한다. 현재 공개본의 실제 Pi 음질·종단 지연·장치 입력 이득별 오차단율은
**Unknown**이며 후속 측정 대상이다.

아래 초기값은 소프트웨어 시험 조건이다. 디지털 출력 제한의 통과를 실제
음압 제한이나 청력보호 성능으로 해석하지 않는다. Python과 운영체제의
실시간 스케줄링을 보증하는 시험도 아니다.

## 재현 방법

깨끗한 Python 환경에 개발 의존성을 설치한 다음 실행한다.

```sh
python -m pip install -e '.[audio,dev]'
tse model fetch
tse model verify
python -m pytest
ruff check .
tse benchmark --frames 10000 --report benchmark.json
```

모델 통합 시험에는 실제 고정 ONNX 파일을 사용한다. 파일이 없는 경우
건너뛴 모델 시험을 모델 검증 통과로 표시하지 않는다. 음성 fixture는
저장소에 포함되므로 정상 음성 시험에는 별도의 네트워크 접근이 필요 없다.

## 정상 음성

[LibriSpeech test-clean](https://www.openslr.org/12/)의 숫자 기준 첫 10명
화자를 선택했다: **61, 121, 237, 260, 672, 908, 1089, 1188, 1221, 1284**.
각 화자의 발화를 숫자 순서로 연결하고 앞 10초를 취한다. 공개 음성 자료는
CC BY 4.0이며 원문 라이선스와 저작자 표기는
[제삼자 고지](../THIRD_PARTY_NOTICES.md)에 포함했다.

[추출 스크립트](../scripts/prepare_speech_fixtures.py)는 공식 아카이브의
체크섬을 검사하고 선택한 파일만 스트림으로 읽는다. 원본 구간·해시·수정
내역은 [manifest](../tests/fixtures/speech/manifest.json)에 고정했다.
각 10초 음성을 피크 **0.10·0.30·0.55**로 조정한 총 30개 조건을 사용한다.
앞에 정확히 1초의 무음을 넣고 마지막 불완전 프레임은 0으로 채운다.

합격 기준은 정상 음성 구간의 보호 상태 재진입 **0건**, 보호 이득이 추가로
차단한 샘플 **0개**다. 원래 음성의 무음이나 최종 리미터 감쇠는 오차단으로
계산하지 않는다. 이 결과를 모든 음량·언어·장치에서의 오차단율로 일반화하지
않는다.

## 충격·포화·잘못된 입력

짧은 충격, 반복 충격, 지속 포화, 음성과 충격의 중첩, 비정상 수치·형태·범위와
장치 overload를 시험한다. 프레임 시작·끝·경계, 임계값 바로 아래·동일·바로
위, 복귀 중 재충격을 포함한다.

| 지표 | 합격 기준 |
|---|---|
| 이상 구간 차단 | 해당 원본 구간의 송신 PCM이 정확히 0, 원음 우회 누출 0건 |
| 최종 피크 | 모든 샘플 유한, 송신·재생 모두 −6dBFS 이하, PCM16 변환 후에도 준수 |
| 보호 이득 복구 | 정상 입력이 계속되면 마지막 이상 프레임 종료 후 256ms 이내 이득 1, 마지막 이상 샘플 기준 272ms 이내 |
| 복귀 연속성 | 샘플당 이득 증가 ≤ 1/2,048, 프레임 경계 연속, 새 이상 없으면 이득 감소 없음 |
| 반복 충격 | 복귀 중 재충격 프레임부터 음소거하고 유지 시간을 다시 계산 |
| 늦은 결과 | 보호 해제·음소거 구간 재생·이미 송신한 구간 재전송 0건 |

복구 시간은 원본 구간과 보호 이득의 시간축에서 판정한다. 실제 재생에는
고정 정렬·수신 지터·장치 지연이 추가된다. 리미터의 100ms 지수형 해제
시정수는 보호 이득의 완전 복귀 시간과 별도로 해석한다.

## 추론 지연과 통신

가상 시계에서 8ms·15ms 추론은 준비 완료 뒤 기한 내 결과를 누락하지 않아야
한다. 17ms·200ms·영구 정지 조건에서도 캡처 제어부의 송신 일정이 늘어나면
안 된다. 정상 구간은 정렬한 원음, 이상 구간은 음소거로 출력한다. 대기열이
가득 차도 입력 이상 검사를 생략하지 않는다.

통신 시험은 두 로컬 프로세스의 동시 송수신과 패킷 손실·중복·순서 변경·재시작·
종료를 확인한다. ±300ppm의 가상 송수신 시계 차이를 각각 한 시간 적용하고
중간에 일시 중단을 주입한다. 수신 버퍼는 항상 8프레임 이하이며 중단 후
재생이 복구되어야 한다. 가상 한 시간은 실제 하드웨어를 한 시간 실행했다는
뜻이 아니다.

지연 표본은 최대 4,096개를 보관하고 누계·최댓값은 전체 실행 기준으로
기록한다. 표본 백분위가 최근 구간만 반영하면 그 범위를 표시한다.

## 실행 기록

2026-09-06 최종 로컬 통합 실행에서 **187개 시험이 4.96초에 통과**했고,
건너뛴 시험은 **0개**였다. 전체 정적 검사와 wheel·sdist 빌드도 통과했다.
이 중 정상 음성 30개 조건에서는 재진입·추가 차단이 모두 0이었다.
고정 음성 자료의 무결성, 지속 포화와 음성·충격 중첩, 임계값 경계,
추론 정지·늦은 결과, 패킷 오류, 장치 시작 중단과 종료 오류의 정리 경로를
포함했다.

공식 배포에서 새로 받은 모델의 무결성과 ONNX 계약을 확인했고, 실제 모델로
10초 음성 파일을 처리하는 실행 명령도 확인했다. 출력은 원본과 같은
160,000샘플이며 정상 구간에서 0이 아닌 출력을 확인했다. 별도 외부 폴더에서 fixture를
다시 생성하여 WAV 10개와 manifest가 바이트 단위로 일치하는지 확인했다.

다음은 로컬 모델 벤치마크의 실측 결과다. **macOS arm64, Python 3.13.5,
NumPy 2.5.2, ONNX Runtime 1.29.0, SoundFile 0.14.0**에서 기본 설정을
사용했다. 고정 사인파 입력으로 100프레임 준비 후 10,000프레임을 측정했다.
모델 해시는 패키지에 고정한 GTCRN 해시와 일치했다.

| 항목 | 결과 |
|---|---|
| 전체 10,000프레임 평균 | 0.719ms |
| 전체 최댓값 | 2.943ms |
| 16ms 이상 처리 | 0 / 10,000프레임 |
| 최근 4,096프레임 p50 / p99 | 0.694ms / 0.931ms |
| 모델 처리 RTF | 0.04494 |

측정 범위는 **GTCRN + WOLA 처리 시간**이다. 보호 제어·오디오 장치·네트워크를
포함하지 않으며 Pi 성능이나 종단 지연을 나타내지 않는다. 모델 처리 RTF는
해당 계산 시간과 오디오 길이의 비율이다.

정확한 측정값·적용 설정·실행 환경은
[로컬 검증 기록](results/local-validation.json)에 보관했다. CI에서 실행하는
설치·시험·빌드 명령은 [워크플로](../.github/workflows/ci.yml)에 정의되어 있다.
이 문서에 기재한 시험 수와 측정값은 로컬 실행 결과다.

## 원격 CI와 독립 설치 검증

동일 코드의 GitHub Actions 검증에서 Linux의 Python 3.11·3.13 작업이 모두 통과했다. 각 작업은 설치, 실제 모델 다운로드·검증, 전체 시험, 정적 검사와 배포 파일 빌드를 실행했다. [검증 실행 기록](https://github.com/sungmin-park-dev/tactical-speech-enhancement/actions/runs/34007305694)을 확인할 수 있다.

원격 저장소를 별도 폴더로 새로 내려받고 새로운 가상환경에 설치한 뒤에도 **187개 시험 통과·건너뜀 0개**와 정적 검사 통과를 확인했다. 이 검증은 로컬 소프트웨어와 CI 환경의 결과이며 실제 Pi 측정을 포함하지 않는다.
